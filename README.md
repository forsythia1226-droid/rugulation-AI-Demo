# 사내규정 AI 에이전트 · 파일럿

대한전선 사내 AI 에이전트 구축 사례 대회 출품 데모입니다.

사내규정을 게시판에서 내려받아 Ctrl+F로 찾던 과정을, 질문 한 번으로 줄이는 AI 창구입니다.
답변마다 근거 조문이 표시되고, 오른쪽 규정 원문에서 해당 문장이 바로 하이라이트됩니다.

## 주요 기능

- 어느 규정인지 몰라도 되는 통합 질문 → 소관 규정 자동 판단
- 답변 근거 조문의 원문 위치 하이라이트
- 여러 규정에 걸친 질문은 관련 규정으로 이어서 안내
- 규정 주관부서가 직접 작성하는 해석 지침
- AI가 답하지 못한 질문의 주관부서 확인 요청

## 안내

- 규정 목록과 업무분류는 사내규정 관리규정 제11조를 따릅니다.
- **조문 본문은 시연을 위해 작성한 가상 조문이며 실제 사규가 아닙니다.**
- 운영 전환 시 사내망에 설치하고 사내 승인 LLM을 연결하는 것을 전제로 합니다.

## 검색 방식

질문과 조문을 **의미 기준으로** 맞춥니다. 글자가 겹치지 않아도 찾습니다.

- "출장 중 식비" → 출장 및 여비규정의 일비 조항 (식비·여비는 글자가 다릅니다)
- "개인 클라우드나 메신저로 파일 전송" → 정보시스템 보안지침

조문 벡터는 빌드 때 미리 계산해 싣기 때문에 **브라우저가 AI 모델을 내려받지 않습니다**(추가 0.8MB, 질의 응답 수 ms).

정확도는 준비 답변 43문항을 기준으로 측정합니다 — `node scripts/eval-retrieval.js`

| | 키워드 검색 | 키워드+임베딩 |
| --- | --- | --- |
| 질문 → 소관 규정 | 84% | **88%** |
| 근거 조문이 검색 1위 | 59% | **67%** |
| 근거 조문이 검색 3위 내 | 76% | **80%** |

## 멀티 에이전트 구조

질문 하나를 세 종류의 에이전트가 나눠 처리합니다.

```
질문 ─▶ Master ─┬─▶ Sub: TES-203 복무규정      ─┐
                └─▶ Sub: TES-201-2 복리후생지침 ─┴─▶ 병합 ─▶ Verify ─▶ 답변
```

| 에이전트 | 역할 | 판단 근거 |
| --- | --- | --- |
| **Master** | 질문이 어느 규정군 소관인지 판단하고 최대 2개를 동시에 호출 | 준비된 질문의 지정 규정 → 조문 검색 점수 |
| **Sub** | 규정군 하나만 담당. 그 규정군의 조문과 주관부서 해석 지침만 본다 | 규정군별로 독립 |
| **Verify** | 답변이 인용한 문장이 현행 조문에 그대로 있는지 대조 | 문자열 대조(LLM 미사용) |

- **Sub를 규정군 단위로 나눈 이유**: 주관부서와 해석 지침이 이미 규정군 단위로 존재해, 에이전트마다 책임 부서가 분명합니다.
- **병합 규칙**: 1순위 답변 본문을 유지하고, 2순위는 본문을 덮지 않고 '이어서 확인할 규정'으로 올립니다. 두 규정이 서로 다른 금액·기한을 말할 때 한쪽을 임의로 고르지 않기 위한 규칙입니다.
- **Verify 실패 시**: 기존 '근거 조문이 개정되었습니다' 경고로 이어지고, `verifyMode:"block"`으로 바꾸면 답변을 보류하고 주관부서 확인 요청으로 넘깁니다.
- **검증은 두 겹**입니다. 배포 전 `scripts/verify-quotes.js`(인용 122건 전수 대조)와 실행 중 Verify 에이전트가 같은 기준으로 다시 확인합니다.

동작 설정은 `js/agents.js`의 `AGENT_CFG` 한 곳에 모여 있습니다.

| 항목 | 기본값 | 설명 |
| --- | --- | --- |
| `fanout` | 2 | Master가 동시에 부를 Sub 개수 |
| `minScore` / `minRatio` | 3 / 0.4 | 2순위 Sub 호출 기준(절대 점수, 1순위 대비 비율) |
| `promoteSecondary` | false | 1순위가 못 답했을 때 2순위 답변으로 대체할지 |
| `verifyMode` | "warn" | 인용 불일치 시 경고 / 보류 |

시연에서는 각 Sub가 실제 LLM을 호출하지 않고 검증된 준비 답변을 반환합니다. 오케스트레이션 경로는 동일하므로, 실시간 전환은 `PROVIDERS`(live/gemini)를 갈아끼우는 것으로 끝나고 `js/agents.js`는 그대로 씁니다.

## 실행 · 배포

- 로컬 확인: `index.html`을 브라우저로 열거나 `python -m http.server 8000` 후 http://localhost:8000
- 시연 계정: 일반 임직원 `user / demo1234`, 규정 관리자 `admin / admin1234` (시연용 로그인이며 보안 수단이 아닙니다)
- 배포: `main`에 push하면 GitHub Actions(`.github/workflows/pages.yml`)가 인용 검증(`node scripts/verify-quotes.js`)을 통과한 경우에만 GitHub Pages로 배포합니다.
  - 최초 1회: 저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 지정
- 데이터(로그인 세션, 관리자 편집, 업로드 파일)는 각 방문자의 브라우저에만 저장됩니다. 실제 사규·실제 파일을 올리지 마십시오.

## 실시간 AI (Gemini) 연동

기본값은 **시연 고정**(검증된 사전 답변)입니다. 실시간 응답을 쓰려면 아래처럼 연결합니다.

### 1) 프록시 방식 (권장 · API 키가 브라우저에 남지 않음)
```bash
cp .env.example .env          # GEMINI_API_KEY=... 채우기 (.env 는 git에 올라가지 않음)
node server/proxy.mjs         # http://localhost:8787
```
- 브라우저에서 http://localhost:8787 접속 → 설정 → 응답 방식 **실시간 AI(Gemini)** 선택
- 프록시 주소는 비워 두면 같은 서버(`/api/chat`)를 사용합니다. 다른 PC에서 접속하면 `http://<서버IP>:8787` 입력
- 키는 서버 환경변수(`GEMINI_API_KEY`)에만 존재합니다.

### 2) 직접 호출 (로컬 테스트용)
설정 화면에 API 키를 입력하면 그 브라우저에만 저장되어 직접 호출합니다.
**공개 주소(GitHub Pages)에서는 키가 노출될 수 있으므로 실제 규정·실제 키로 사용하지 마십시오.**

### 안전장치
- 호출 실패(키 오류, 쿼터 초과, 네트워크 오류, 20초 초과)는 모두 `try/catch`로 잡아
  **검증된 사전 답변으로 자동 전환**하고, 답변 위에 전환 사유를 표시합니다. 시연이 끊기지 않습니다.
- System Prompt에 출처 명시, 사내 규정 외 질문 거절(가드레일), 마크다운 출력 포맷을 강제합니다.
- 무료 등급은 입력 데이터가 서비스 개선에 사용될 수 있습니다. **실제 사규로는 사용하지 마십시오.**
